# ADR-004: Mock Provider and Deterministic Offline Fallback

## Status
Accepted

## Context
Automated continuous integration (CI) environments, unit tests, and developers without high-end GPUs or running Ollama daemons must be able to boot, test, and develop against the platform without failures. Furthermore, if a local Ollama server crashes or times out during execution, the CEO agent must fail gracefully rather than crashing or fabricating hallucinatory output.

## Decision
We implement a `MockLLMProvider` as a first-class provider implementation:
1. `MockLLMProvider` produces deterministic, structured responses grounded in the prompt context without network or GPU usage.
2. In `OllamaLLMProvider`, if the daemon is unreachable or errors, it returns an explicit error object (`error: str`) without silent fabrication.
3. The CEO orchestration engine detects provider errors and falls back to a deterministic bullet-point synthesis of verified agent evidence.

## Alternatives Considered
1. **Failing hard whenever Ollama is unavailable**:
   - *Rejected*: Prevents unit test suites from passing in standard CI runners and prevents rapid offline UI testing.
2. **Silently fabricating mock responses when Ollama fails**:
   - *Rejected*: Violates core architectural requirement: "Never silently replace a failed real model call with fabricated success."

## Consequences & Trade-offs
- **Positive**:
  - Full test suite runs in 0.4 seconds without any external daemon.
  - Transparent UI indicator showing whether response was generated by Mock or Ollama.
- **Negative / Trade-offs**:
  - Mock mode text is rule-based and does not exhibit open-ended reasoning.
